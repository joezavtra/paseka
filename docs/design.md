# paseka — дизайн v1

Дата: 2026-08-17

> Проектный документ: писался до кода и задавал архитектуру. По устройству
> системы он актуален, по составу возможностей — сверяйтесь с §16.1 «Что
> реализовано» и с README: часть заявленного здесь в v1 не вошла (например,
> `--export`), часть решений по ходу изменилась. Источник истины — код.
> Проект назывался `gource-reborn`, пока имя не начало обещать преемственность
> gource, которой у него нет.

## 1. Цель

Интерактивный визуализатор истории git-репозитория. Запускается одной командой в
папке проекта, открывает вкладку браузера с живым деревом кода, над которым
работают контрибьюторы.

Референсы: [gource](https://gource.io) — анимация истории во времени;
[CodeFlower](https://github.com/fzaninotto/CodeFlower) — force-directed дерево
файлов. Из первого берётся ощущение растущего организма, из второго — читаемая
структура кода. Ключевое отличие от обоих: инструмент интерактивен, а не
рендерит видео.

## 2. Скоуп v1

Входит:

- Гибридная сцена с двумя режимами — воспроизведение и исследование.
- Парсинг истории до ~50 000 коммитов без внешней БД.
- Инспекция узла: hover-тултип и панель с историей файла.
- Фильтры (авторы, путь, расширение) и поиск. Фильтр **гасит** непопавшее, а не
  скрывает: дерево всегда остаётся целым.
- Управление камерой: zoom, pan, фокус на поддереве.
- Управление видимостью поддеревьев: скрыть или свернуть любую папку.
- Запуск через `npx` в папке репозитория, автооткрытие браузера.
- Экспорт самодостаточного HTML-файла.

Не входит (сознательно отложено):

- Watch-режим с дозагрузкой новых коммитов через SSE.
- Запись видео и GIF.
- CLI-флаги фильтрации (`--since`, `--author`, `--path`): вся фильтрация — в UI.
- Отслеживание переименований (`git log -M`).
- Монорепозитории 500k+ коммитов: потребуют персистентного индекса и LOD.
- Воспроизведение по календарным датам со сжатием пауз.

## 3. Принятые решения и их обоснование

| Решение | Почему |
|---|---|
| Гибрид: одна сцена, два режима | Воспроизведение и исследование нужны оба, но общий layout и общий движок состояния позволяют не строить две системы. |
| Живая force-симуляция, узлы входят и выходят по времени | Дерево реально растёт — это главный визуальный эффект gource. Статичный union-layout его обесценивает. |
| Данные едут одним пакетом | Нет БД, нет дозапросов, экспорт HTML получается почти бесплатно. |
| Курсор времени — индекс коммита, не дата | Иначе полугодовой перерыв в истории превращается в мёртвый экран. |
| Фильтр гасит, а не скрывает | Сохраняется пространственный контекст: видно, где в дереве живёт то, что нашлось. |
| Скрытие поддерева, наоборот, убирает узлы | Цель обратная — убрать шум и освободить площадь. |
| По умолчанию не скрыто ничего | Инструмент не должен молча прятать данные; выбор за пользователем. |

## 4. Архитектура

Один npm-пакет `paseka` с `bin`. Две сборки: Node (CLI + сервер) и
web-бандл (Vite). Формат pack — общий код, декодируется в обоих рантаймах.

Стек: TypeScript, Node 22+, Vite, d3-force, обычный DOM без фреймворка,
vitest, Playwright.

### 4.1 Модули

| Модуль | Ответственность | Зависимости |
|---|---|---|
| `src/git/repo` | Обнаружение `.git`, проверки репозитория | node:child_process |
| `src/git/log-stream` | spawn `git log`, стриминг stdout чанками | node:child_process |
| `src/git/parse` | Чистая функция: текст → `RawCommit[]` | — |
| `src/model/build` | Чистая: `RawCommit[]` → `Pack` | — |
| `src/pack/encode`, `src/pack/decode` | `Pack` ↔ `ArrayBuffer` | — |
| `src/server/serve` | node:http: статика + `/api/pack` | pack |
| `src/export/inline` | Pack + бандл → один HTML | pack |
| `src/cli/main` | Разбор аргументов, оркестрация, открытие браузера | всё выше |
| `web/time/engine` | Чистая: `(Pack, T)` → живые узлы, рёбра, размеры, недавние события | pack |
| `web/state/visibility` | Чистая: `(Pack, liveSet, VisibilitySpec)` → отображаемые узлы и рёбра | pack |
| `web/state/filter` | Чистая: `(Pack, FilterSpec)` → `Float32Array` альф | pack |
| `web/layout/worker` | d3-force в Web Worker; вход — diff узлов, выход — позиции | — |
| `web/render/*` | Canvas: позиции, альфы, размеры, события → пиксели | — |
| `web/ui/*` | Панели на обычном DOM | state |

Принцип границ: вся логика — чистые функции без DOM и без процессов, тестируются
напрямую. Побочные эффекты изолированы в трёх местах: `log-stream`, `serve`,
`render`.

### 4.2 Поток данных

```
git log (stream) → parse → RawCommit[] → build → Pack → encode
                                                          │
                                        HTTP /api/pack ───┴─── вшито в HTML
                                                          │
браузер: decode → Pack
   ├─ time/engine     : T → { liveNodes, liveEdges, sizes, recentEvents }
   ├─ state/visibility: liveSet + VisibilitySpec → renderNodes, renderEdges, representative
   ├─ layout/worker   : diff узлов → Float32Array позиций (transferable)
   ├─ state/filter    : FilterSpec → Float32Array альф
   └─ render/scene    : всё вышеперечисленное → canvas
```

Воркер и рендер развязаны двойным буфером `Float32Array`: воркер считает тики в
своём темпе, рендер каждый кадр берёт последний готовый буфер и интерполирует
позиции. Просадка симуляции не роняет частоту кадров.

## 5. Сбор данных из git

Один вызов:

```
git -c core.quotepath=false log --reverse --no-merges --no-renames --raw --numstat \
    --pretty=format:$'\x01%H\x1f%an\x1f%ae\x1f%at\x1f%s'
```

`\x01` разделяет записи, `\x1f` — поля. Парсер стримовый: буферизует только хвост
неполной записи, не держит вывод целиком.

Решения по флагам:

- `--raw --numstat` вместе — **обязательно оба**. Проверено на живом git: `--numstat`
  и `--name-status` перекрывают друг друга, и печатается только один блок, тогда как
  `--raw --numstat` печатает оба подряд. Один `--numstat` не даёт статуса файла:
  строка `0	42	path` одинаково означает и «удалён», и «вырезали 42 строки».
  Без статуса файлы никогда не умирают. Raw-блок идёт первым и является источником
  истины по составу и статусу (`A`/`M`/`D`), numstat-блок добавляет числа строк и
  признак бинарности (`-	-`). Raw-строки узнаются по ведущему `:`.
- `--no-merges` — иначе изменения учитываются дважды. **Следствие, выявленное при
  реализации:** живое множество путей может расходиться с реальным деревом HEAD.
  Если файл удалён на одной ветке, изменён на другой, а слияние разрешено в пользу
  удаления, то коммит слияния — единственное место, где записано удаление, и без
  него модель считает файл живым. На HEAD это редкость, но при перемотке по времени
  расхождение будет видно на каждом кадре. Закрывать в срезе 3: либо сверять финальное
  состояние с `git ls-tree HEAD`, либо разбирать слияния отдельным проходом.
- **Время автора немонотонно.** `%at` — дата автора, а `--reverse` упорядочивает по дате
  коммита. После rebase, cherry-pick или `git am` порядок дат автора нарушается.
  Всё, что выводится из времён (границы периода, отображение даты в индекс коммита для
  слайдера), обязано считаться через минимум и максимум либо через явную сортировку,
  а не полагаться на порядок массива.
- `--no-renames` — переименование становится «умер там, родился здесь». Разбор
  `{a => b}`-форм numstat неприятен, а визуально переезд файла честно выглядит
  как переезд. Кандидат в v2.
- `core.quotepath=false` — иначе git отдаёт не-ASCII пути в escape-кавычках.
- Ветка по умолчанию — текущий HEAD.

Бинарные файлы дают `-\t-` в numstat: получают флаг `binary` и нулевой прирост
строк.

## 6. Формат Pack

Всё в typed arrays, строки — в пулах, связи «один-ко-многим» в CSR
(offsets + плоский массив).

```
meta       repoName, head, commitCount, firstTs, lastTs, packVersion
paths[]    пул путей — файлы И директории, id = индекс
authors[]  пул { name, email }
commits    ts:U32  authorId:U32  hash[]  subject[]  eventStart:U32 (CSR)
events     pathId:U32  commit:U32  kind:U8 (add|modify|delete)  added:U32  deleted:U32  flags:U8
tree       parent:U32 на каждый путь
lifetimes  CSR: путь → интервалы [рождение, смерть) в индексах коммитов
pathEvents CSR: путь → индексы его событий + префиксная сумма строк
```

Ориентир объёма: 50k коммитов / ~500k событий ≈ 13 МБ, gzip ≈ 4 МБ.

Кодек: magic `GRPK`, версия, JSON-заголовок (пулы и карта секций), далее бинарные
секции с выравниванием по 4 байта. Декод создаёт views на один `ArrayBuffer` —
без копирования и без `JSON.parse` по горячим данным. Сервер отдаёт с
`Content-Encoding: gzip` (сжимается один раз, кэшируется в памяти). Экспорт
кладёт тот же gzip в base64 и распаковывает через `DecompressionStream('gzip')`.

## 7. Движок времени

Курсор — индекс коммита. Слайдер тоже работает в индексах, а дата показывается
подписью под ним; воспроизведение идёт «коммитов в секунду» (скорость 0.5x–8x).
**Гистограмма под слайдером обязана быть в той же оси.** Раскладка по времени
над шкалой индексов означает, что пользователь тянет ползунок к видимому
всплеску и попадает в другой коммит; плотность же коммитов по индексу
равномерна по построению и бесполезна. Поэтому столбик — это объём изменений
файлов в диапазоне индексов корзины.

Две операции, намеренно разные по цене:

- `step()` — события следующего коммита дают дельту живых узлов напрямую.
  Горячий путь воспроизведения, O(события коммита). Отдельного шага назад нет:
  он делается тем же `seek`, что и перемотка.
- `seek(T)` — полный пересчёт: проход по путям с бинарным поиском в интервалах
  жизни, ~1 мс на 20k путей. Только при драге слайдера.

Размер файла на момент T — бинарный поиск в префиксной сумме строк этого пути.
Директория жива, пока у неё есть живые потомки: держим счётчик детей и обновляем
вверх по дереву. Для лучей авторов — кольцевой буфер последних событий с
затуханием.

**Важно про `pathIsDir`.** Флаг означает «путь хоть раз выступал родителем», и это
свойство всей истории, а не момента времени: один и тот же путь бывает файлом в
одни моменты и каталогом в другие (`utils.ts` → каталог `utils/` — обычное дело при
разрастании модуля). Поэтому живость пути определяется наличием собственных
интервалов жизни, а `pathIsDir` используется только рендером — для выбора радиуса и
цвета. Ошибка здесь не роняет программу: узел просто молча исчезает со сцены на всех
кадрах. При реализации среза 1 она была допущена и поймана финальным ревью.

## 8. Layout

Force-симуляция (d3-force) в Web Worker, работает постоянно. Рёбра — связи
«родитель → потомок», отталкивание Barnes-Hut, слабое притяжение к центру.

Узлы входят в симуляцию при рождении файла и выходят при удалении. Позиция
удалённого узла запоминается: вернувшийся файл всплывает там же. Стартовые
позиции детерминированы по seed, чтобы два прогона на одном репозитории давали
похожую картинку.

Изменения множества узлов приходят в воркер как diff — одинаково для шага
времени, перемотки и изменения видимости. Отдельного механизма не требуется.

## 9. Видимость поддеревьев

Две операции над директорией, обе из панели-навигатора (раскрывающееся дерево
папок с чекбоксом и стрелкой):

**Скрыть** — поддерево выходит из живого множества: узлы удаляются из симуляции,
рёбра пропадают, граф релаксирует и занимает освободившееся место.

**Свернуть** — поддерево заменяется узлом-агрегатом: радиус ∝ сумме строк
потомков, подпись «имя папки · N файлов», нейтральный цвет. События внутри
адресуются агрегату — луч автора бьёт в него, папка вспыхивает. Клик
разворачивает обратно.

Модуль `state/visibility`:

```
(Pack, liveSet, VisibilitySpec) → { renderNodes, renderEdges, representative }
```

`representative: Uint32Array` — для каждого пути его отображаемый представитель:
он сам, ближайший свёрнутый предок, либо «нет» если скрыт. Считается одним
проходом сверху вниз, O(путей), кэшируется, пересчитывается только при изменении
спеки. Через него адресуются лучи авторов и клики инспектора.

По умолчанию не скрыто ничего. В панели есть кнопка «скрыть типовой шум»
(`node_modules`, `vendor`, `dist`, `build`, `target`, `.min.*`, lock-файлы) —
применяется только по явному клику. Состояние видимости сохраняется в
`localStorage` по имени репозитория.

## 10. Фильтрация и поиск

`FilterSpec` — авторы, glob пути, расширения, строка поиска. Чистая функция даёт
`Float32Array` альф на путь: 1.0 внутри фильтра, ~0.12 снаружи. Топология и
симуляция не трогаются: дерево остаётся целым.

Директория и агрегат получают максимум альф своих потомков — иначе подсвеченный
файл повиснет на погасшей ветке. Переход альфы интерполируется за ~200 мс.

Поиск (`/`) инкрементальный, даёт отдельную маску попаданий для обводки и
фокусирует камеру на первом совпадении.

## 11. Рендеринг

Один canvas 2D, DPR-aware. Порядок слоёв: рёбра → директории → файлы → лучи
авторов → значки авторов → подписи.

- Радиус файла ∝ √числа коммитов, задевших файл (не строк: размер показывает,
  где кипит работа, а сгенерированный файл на десять тысяч строк, тронутый
  однажды, не должен спорить размером с ядром проекта); цвет по расширению (топ-N расширений — устойчивые цвета
  из палитры, хвост — серый).
- Culling по видимому прямоугольнику; на дальнем зуме подписи и рёбра
  отключаются по порогу.
- Подписи — только для крупных, наведённых и найденных поиском узлов.

Контрибьюторы: у каждого автора, активного в текущем окне, своя позиция —
пружина к центроиду файлов, которые он сейчас трогает, плюс слабое взаимное
отталкивание. Луч автор→файл живёт ~1.2 с с затуханием; файл на попадании
вспыхивает (временный прирост радиуса и яркости). Аватар — кружок с инициалами и
цветом из хэша email; сетевых запросов нет, инструмент работает оффлайн.

## 12. UI

Два режима переключаются кнопкой:

- **Воспроизведение** — камера автоследует за активностью, боковые панели
  свёрнуты, лучи авторов активны.
- **Исследование** — пауза, ручная камера, панели открыты.

Панели (обычный DOM без фреймворка; canvas живёт отдельно):

- Снизу — транспорт: play/pause, скорость, слайдер с гистограммой активности,
  текущая дата и хэш.
- Слева — фильтры (авторы с долями коммитов, glob пути, чипы расширений) и
  навигатор дерева с управлением видимостью.
- Справа — инспектор по клику на узел: путь, строки, дата рождения, топ-
  контрибьюторы, спарклайн активности, последние коммиты.
- Легенда расширений.

## 13. CLI, сервер, экспорт

```
npx paseka [путь]               # по умолчанию — текущая папка
  --port <n>                    # по умолчанию свободный, начиная с 7420
  --no-open                     # не открывать браузер
  --export <файл.html>          # НЕ РЕАЛИЗОВАНО в 0.1.0, см. §16.1
```

Сервер (node:http) поднимается сразу и открывает вкладку; `/api/pack` отвечает,
когда парсинг завершён, страница до этого показывает прогресс. Прогресс парсинга
пишется и в терминал.

`--export` в 0.1.0 не реализован — он остаётся в этом разделе как проектное
намерение, перенесённое в срез 6. Задумано так: вшивает pack и web-бандл в один
самодостаточный HTML. Экспорт делает
CLI, поэтому он берёт дефолтную видимость — состояние открытой вкладки в файл не
переносится.

## 14. Обработка ошибок

Жёсткие (сообщение + ненулевой код возврата):

- Папка не является git-репозиторием — с подсказкой, что делать.
- `git` не найден в PATH.
- Пустая история.
- `git log` завершился с ошибкой — показываем его stderr.

Мягкие (предупреждение, работа продолжается):

- Shallow clone — история обрезана.
- Репозиторий заметно больше расчётного — предупреждение об объёме памяти.
- Порт занят — берём следующий свободный.
- Браузер не открылся — печатаем URL.

В браузере: pack не загрузился или повреждён — экран ошибки с текстом причины.

## 15. Тестирование

Vitest:

- `git/parse` — фикстуры: бинарник, пустой коммит, юникод в путях, многострочные
  и пустые subject, CRLF.
- `model/build` — интервалы жизни для сценария «создан → удалён → создан
  заново», префиксные суммы строк, сборка дерева директорий.
- `pack` — property-тест на round-trip encode/decode.
- `time/engine` — **property-тест против наивной эталонной реализации**: для
  случайных T оба способа дают одинаковое множество живых узлов и одинаковые
  размеры. Главный тест проекта: здесь прячутся все инкрементальные баги.
- `state/visibility` — property-тест: представитель определён корректно при
  любой комбинации скрытий и сворачиваний.
- `state/filter` — альфы, наследование альфы директориями и агрегатами.

Интеграционный: скриптом создаётся временный git-репозиторий, гоняется CLI,
проверяется содержимое pack.

E2E (Playwright): запуск на фикстурном репозитории — canvas отрисовался,
play/pause работает, клик даёт инспектор, фильтр меняет альфы, скрытие папки
убирает узлы. Скриншот-регресс не берём: физика недетерминирована, тесты будут
флейкать.

## 16. Перф-бюджеты

Синтетический репозиторий 50k коммитов / ~20k путей:

- Парсинг и сборка pack — ≤ 20 с, память процесса ≤ 1 ГБ.
- Time-to-first-frame после загрузки pack — ≤ 2 с.
- Воспроизведение — ≥ 30 fps при 20k живых узлов.
- `seek` по слайдеру — ≤ 16 мс.

## 16.1. Что реализовано

**Срезы 1 и 2** (ветка `feat/data-pipeline`, в `main`): сбор истории, модель
данных, бинарный формат, сервер, загрузка в браузере, живое множество на HEAD,
force-раскладка в воркере, canvas с зумом и панорамированием, E2E.

**Срез 3** (ветка `feat/time-playback`): движок времени с дешёвым шагом и полным
пересчётом, единая нумерация узлов по идентификатору пути, протокол воркера на
разнице состава с памятью позиций ушедших, воспроизведение, панель транспорта с
гистограммой активности. Все три долга, записанные здесь после среза 1, закрыты:
сверка с деревом HEAD, diff-протокол воркера и числовая палитра вместо строковых
цветов.

**Срез 4** (ветка `feat/authors-beams`): кольцевой буфер событий последних секунд
с затуханием, значки контрибьюторов с инициалами и именем, изогнутые лучи к
задетым файлам, вспышки на файлах, поле авторов с пружиной к центроиду и
взаимным отталкиванием. Синтетические удаления от сверки с деревом HEAD
исключены из затронутых путей — иначе последний коммит стрелял бы лучами по
файлам, которых автор не касался.

Оттенки значков ограничены полосами, вычисленными из палитры узлов: без этого
цвет одного из авторов совпадал с цветом файлов `.py` с точностью до градуса, и
значок исчезал среди узлов. Полосы считаются из палитры при загрузке, поэтому
правка палитры автоматически перекрашивает авторов; вырожденный случай (палитра
плотнее отступа) даёт откат к полному кругу с предупреждением, а не молча
негодный цвет.

**Срез 5а** (ветка `feat/filtering-visibility`): фильтр по авторам, образцу пути
и расширению, гасящий непопавшее без ущерба дереву; скрытие и сворачивание
поддеревьев; левая панель с фильтрами и навигатором дерева; выбор видимости
переживает перезагрузку.

Два правила, которые нельзя смешивать, разведены по разным модулям и разным
массивам. **Фильтр гасит**: `computeAlpha` даёт по альфе на путь, у каталога —
максимум по потомкам, так что путь к найденному виден всегда; топология и
симуляция не трогаются. **Видимость убирает**: `resolveVisibility` даёт маску
рисуемых и представителя на каждый путь, скрытое поддерево уходит из симуляции
целиком, свёрнутое схлопывается в один узел. Долг среза 4 закрыт: луч
разрешается через представителя и берёт там же свою яркость — «куда бьёт и
насколько ярок» осталось одной строкой в одном месте.

Сопоставление с образцом сделано двумя указателями, а не регулярным выражением:
построенное из образца `RegExp` на десяти звёздах считалось 15 секунд, а поле
фильтра срабатывает на каждое нажатие клавиши. Видимость сохраняется строками
путей, а не идентификаторами: идентификаторы сдвигаются при вливании давно
живущей ветки, и сохранённый номер назавтра означает другую папку.

Долг среза 4 по хранилищу узлов тоже закрыт: `applyUpdate` разворачивает маску
структурно и рождает недостающих предков рекурсивно, а не доверяет списку
добавленных, — маска видимости это доверие как раз и нарушает.

**Срез 5b** (ветка `feat/inspector-search`): карточка узла по клику справа, поиск
с обводкой найденного и фокусом камеры, подписи узлов, наведение мышью, вторая
ось цвета значков авторов.

Появилось недостающее звено — обратное отображение «точка экрана → путь»
(`web/render/pick.ts`): прямое накрытие сильнее близости, среди накрывающих
выигрывает нарисованный последним, то есть файл поверх своего каталога.
Допуск в экранных пикселях переводится в мировые вызывающим, поэтому сам
подбор не знает ни про камеру, ни про DOM.

Три оси, которые нельзя смешивать, теперь разведены полностью: **фильтр
гасит** (`alpha`), **поиск обводит** (`hit`, своя постоянная яркость — иначе
поиск по отфильтрованному дереву не находил бы ничего видимого), **видимость
убирает** (`representative`, `drawn`). Через представителя адресуются лучи,
обводка поиска, подписи и клики — правило одно на всех.

Карточка узла показывает состояние **на текущем курсоре целиком**, включая
спарклайн: смешивать в одном окне «сейчас» и «за всю историю» нельзя, столбик
из будущего означал бы, что и число строк оттуда же. Коммит автора считается
один раз, даже если он задел десять файлов внутри каталога.

Камера едет к найденному по Enter, а не по каждой букве: обводка обновляется
инкрементально, а дёргающееся на каждое нажатие дерево — потеря контекста, а
не помощь. Если у найденного узла ещё нет позиции от раскладки, фокус
откладывается до ближайшего сообщения воркера. Для этого в протокол раскладки
добавлена эпоха: главный поток нумерует `update`, воркер возвращает номер
последнего применённого, и признак «узел размещён» поднимается по маске той
эпохи, а не по текущей маске главного потока. Прежняя версия выводила
размещённость у себя — та же ошибка «потребитель выводит то, чем владеет
отправитель», которую этот проект ловил в каждом срезе.

Долги среза 5b закрыты: вторая ось цвета значков (светлота поверх оттенка,
нижний уровень выбран по расчёту контраста к фону сцены, а не на глаз),
отдельная ось для подсветки поиска, обратное отображение «точка → путь»,
подпись свёрнутой папки «имя · N файлов». Два перенесены дальше и записаны
ниже.

Расхождение двух счётчиков файлов разрешено явно: подпись отвечает «сколько
схлопнуто в этот кружок», карточка — «сколько живого внутри»; когда они
расходятся (внутри свёрнутой папки что-то скрыто), карточка называет и
разницу. Сводить их к одному числу нельзя — одна из формулировок начала бы
врать.

Долги, оставленные срезу 6 и дальше:

- **Вписывание камеры считает центры узлов без учёта радиусов** — крупный узел
  у края может частично уйти за экран. Полосы панелей слева и справа оно уже
  учитывает.
- **Готовность холста не означает, что картинка устоялась:** камера въезжает в
  плотный ком новорождённых узлов и выезжает обратно 6–8 секунд, что читается
  как непрошеный рывок на старте.
- **Две панели занимают около 660 пикселей.** На окне уже примерно 1100 px
  дереву остаётся полоса, в которой гаснут подписи, а на 860 px картинка
  нечитаема, при этом низ экрана пустует. Нужно продуктовое решение (перекрывать
  холст карточкой вместо вычитания полосы, либо сворачивать левую панель), а не
  правка одной строки.
- **§11 не выполнен в части рёбер:** порог отключения рёбер на дальнем зуме не
  сделан нигде и до этого среза нигде не был записан. Подписи такой порог имеют.
- **Наведение сделано подписью на холсте, а не тултипом с данными** (§2, §12).
  Сознательное сокращение: инспектор по клику даёт те же данные полнее.
- **`focusOn` необратимо объявляет камеру ручной:** один поиск — и изменение
  размера окна больше никогда не вписывает дерево само.
- **Кадр получил два безусловных прохода по всем путям** — подбор наведения
  (пока указатель над холстом) и отбор подписей. Слой обводки ранний выход уже
  имеет. На 20k путях это единицы процентов бюджета кадра, но направление
  ухудшающее.
- **Списки авторов и коммитов в карточке пересобираются раз в 250 мс** во время
  воспроизведения, поэтому выделить текст коммита для копирования не удаётся.
- Полей ввода, гоняющих `toLowerCase` по всем путям на каждое нажатие, теперь
  два; таблицы путей в нижнем регистре по-прежнему нет.
- У подписей и холста в целом нет эквивалента для скринридера.

Долги, оставленные срезу 6:

- Перенос разницы в сцену стоит прохода по всему дереву на каждый коммит, тогда
  как сам шаг движка стоит по числу событий коммита.
- Сборка слоёв активности выделяет короткоживущие объекты пропорционально числу
  живых событий (потолок — 512). На бюджете кадра это доли процента, но
  направление ухудшающее: размен был сделан осознанно, ради единственного места
  истины вместо копилок по всем авторам.
- `resolveVisibility` пересчитывает представителей на каждое применение, хотя
  они зависят только от пакета и спецификации видимости, а не от курсора.
- Пакетные фильтры (авторы, расширения) пересчитывают альфы полным проходом по
  всем путям; на 20k путях это заметно только при удержании клавиши в поле.
- `describeNode` и `pickNode` — тоже полные проходы по всем путям; первый
  платится по клику и не чаще раза в 250 мс, второй — покадрово при наведении.

## 17. Порядок реализации

Работа режется на вертикальные срезы, каждый заканчивается чем-то, что можно
запустить и увидеть:

1. **Данные**: `git/*` → `model/build` → `pack/*`, юнит-тесты. Результат — CLI,
   который печатает статистику по репозиторию.
2. **Первый кадр**: сервер, загрузка pack в браузере, статичный force-layout
   текущего состояния дерева на canvas. Результат — картинка.
3. **Время**: `time/engine`, воркер с diff-ами, транспорт и слайдер. Результат —
   дерево растёт, воспроизведение работает.
4. **Авторы**: лучи, вспышки, значки контрибьюторов.
5. **Взаимодействие**: камера, инспектор, фильтры, поиск, видимость поддеревьев.
6. **Упаковка**: `--export`, обработка ошибок, E2E, замеры перф-бюджетов.

## 18. Кандидаты в v2

Watch-режим через SSE, отслеживание переименований, запись видео, CLI-флаги
фильтрации, WebGL-рендер при упоре в потолок Canvas 2D, воспроизведение по
календарным датам со сжатием пауз, персистентный индекс для монорепозиториев.
