# Как это писалось

Пять документов ниже — исходные планы реализации, по одному на вертикальный
срез: данные и первый кадр, время и воспроизведение, авторы и лучи, фильтры и
видимость поддеревьев, инспектор и поиск. Они писались **до** кода, как задание
на работу, и в них осталось то, чего обычно не остаётся нигде: почему pack
устроен именно так, почему фильтр гасит непопавшее, а не скрывает, почему
сопоставление пути с образцом сделано двумя указателями, а не регулярным
выражением (построенное из образца `RegExp` на десяти звёздах считалось
пятнадцать секунд, а поле фильтра срабатывает на каждое нажатие клавиши), какие
долги оставались следующему срезу и чем они закрывались.

Читать их стоит как запись хода разработки, а не как документацию. Жанр —
задание исполнителю, отсюда чек-боксы, императив и разделы «чего НЕ делать».
Часть решений по ходу изменилась, и планы этого не знают: источник истины — код
и [docs/design.md](../design.md), где сведено, что реализовано и какие долги
остались открытыми.

Проект разрабатывался с помощью ИИ-агента по этим планам: каждый срез —
написанный заранее план, затем реализация по нему с ревью на каждой задаче.
Отсюда и объём текста, и его тон. В самих планах остались следы этого процесса —
разборы найденных дефектов и решения, принятые по ходу.
