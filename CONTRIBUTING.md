# Как участвовать

Спасибо за интерес. Ниже — то, что нужно знать до первой правки: в проекте
несколько неочевидных соглашений, и без них первый же PR будет красным.

## Начать

```bash
git clone https://github.com/joezavtra/paseka.git
cd paseka
npm ci
npm run build
node dist/node/cli/main.js .
```

Нужен Node 22+ и `git` в `PATH`.

## Проверки

```bash
npm run typecheck              # tsc --noEmit
npm test                       # юнит-тесты, ~2 секунды
npm run build                  # обе половины: dist/node и dist/web
npx playwright install chromium
npm run test:e2e               # сквозные, требуют собранного dist/web
```

CI гоняет ровно это на Node 22 и 24. Линтера и форматтера в проекте нет
намеренно — их появление переформатировало бы весь репозиторий одним шумным
коммитом.

## Соглашения, которые легко нарушить по незнанию

**Язык.** Комментарии, докблоки, тексты интерфейса, сообщения CLI и названия
тестов — по-русски. Идентификаторы, имена файлов и сообщения коммитов —
по-английски. Сообщения коммитов — [Conventional
Commits](https://www.conventionalcommits.org): `feat(render): ...`, `fix(ui): ...`.

**ESM с расширением.** Все относительные импорты пишутся с `.js`, даже когда
рядом лежит `.ts`: `import { foo } from './bar.js'`. Так требует ESM в Node.

**TypeScript.** `strict: true`, но `noUncheckedIndexedAccess` **выключен** —
индексация типизированных массивов даёт `number`, а не `number | undefined`.

**Границы.** В `src/` (CLI, парсинг git, модель, сервер) можно только
`node:`-модули — никакого DOM. В `web/` наоборот: никаких `node:`-модулей,
браузер и только браузер.

**`Math.random()` запрещён во всём проекте.** Раскладка обязана быть
воспроизводимой: два запуска на одном репозитории дают похожую картинку. Для
случайности есть `makeRng` (mulberry32) в `src/util/rng.ts`, для уникальных
идентификаторов в DOM — счётчик экземпляров.

**Тесты.** Vitest без `globals`: `describe`, `it`, `expect` импортируются явно.
Среда с DOM включается пофайлово докблоком в первой строке файла:
`// @vitest-environment happy-dom` — глобально её включать нельзя, иначе
node-тесты начнут молча зависеть от несуществующего браузера.

**Массивы по узлам** индексируются идентификатором пути, и идентификатор
родителя всегда меньше идентификатора потомка — на этом стоят однопроходные
обходы дерева в обе стороны.

## Что ценится в правках

Комментарий объясняет **почему**, а не **что**: «иначе погашенная ветка осталась
бы соединена яркими линиями и читалась бы как активная» полезнее, чем «берём
минимум из двух альф».

Тест должен падать на коде до правки. Если тест зелёный и до, и после — он
ничего не сторожит; в этом проекте такие ловили не раз, и каждый раз оказывалось,
что данные подобраны так, что правильное и ошибочное поведение совпадают.

Числа в коде — из замера, а не на глаз. Порог контрастности, радиус действия
силы, длина ребра: если значение выбрано, в докблоке рядом должно быть сказано,
чем оно обосновано.
